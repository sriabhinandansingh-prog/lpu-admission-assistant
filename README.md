# LPU Admission Assistant

A static admission-counsellor chatbot for Lovely Professional University, deployable on GitHub Pages with no server, no build step and no API key required.

**Live:** https://sriabhinandansingh-prog.github.io/lpu-admission-assistant/

## What it does

- Answers questions about courses, eligibility, fees policy, scholarships, the admission process, LPUNEST, hostel and campus.
- Replies in English, Hindi, Hinglish or Punjabi, matching whichever the student uses.
- Refuses to invent fees, cutoffs, deadlines or scholarship amounts. It says it does not have a verified figure and links to the official portal.
- Never claims to check an application, take a payment or guarantee admission.
- Works with zero backend, which is the only thing GitHub Pages can host.

## Files

```
index.html              chat shell
styles.css              styling
app.js                  language detection, intent matching, answer builders
data/knowledge.json     the knowledge base - edit this, not the JS
.nojekyll               tells Pages to serve files as-is
```

## Run locally

Open the folder over HTTP, not as a `file://` path, or the JSON fetch is blocked:

```bash
python3 -m http.server 8000
```

Then visit http://localhost:8000

## Editing the knowledge base

Everything factual lives in `data/knowledge.json`: programmes, admission steps, scholarship categories, hostel notes, FAQs. Add a programme by copying an entry in the `programmes` array and changing the fields.

Two rules worth keeping:

1. **Do not add fee numbers, cutoffs or deadlines to this file unless you have verified them on admission.lpu.in for the current session.** The assistant is built to say "I don't have a verified figure" rather than guess, and that is a feature.
2. **Set `meta.verified` to `true` only after someone has checked every row against the official site.**

## Optional: model mode

The built-in engine is rule-based, which is why it is honest but limited. A visitor can open **Settings** and paste an API key plus an OpenAI-compatible endpoint and model. Replies are then generated by that model, grounded by the same knowledge base, and the key is stored only in that visitor's `localStorage`.

Never hardcode a key in this repository. GitHub Pages serves everything publicly, and a committed key is a leaked key.

## Deploy

Already deployed via GitHub Pages from the `main` branch root. To update:

```bash
git add -A
git commit -m "Update knowledge base"
git push
```

Pages rebuilds automatically within a minute or two.

## Limits

- Static hosting means no lead capture, no admin view and no server-side logging. If you need counsellors to receive enquiries, that needs a backend (a form endpoint, a database, or the Base44 app version).
- The knowledge base is a starting structure, not an audited prospectus. Verify before putting this in front of real applicants.
- Not affiliated with or endorsed by Lovely Professional University. It is an independent guide that links to the official portal.
